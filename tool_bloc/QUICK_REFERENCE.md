# Quick Reference - Mason BLoC Templates

## Quick Commands

```bash
# Install/Update Mason
dart pub global activate mason_cli

# Get bricks
mason get

# List available bricks
mason list

# Create POST feature with UI
mason make post_view --module user --name login

# Create GET feature with UI
mason make get_view --module todo --name listing

# Create POST integration only (no UI)
mason make post_integration --module user --name update_settings

# Create GET integration only (no UI)
mason make get_integration --module analytics --name fetch_stats
```

## Template Comparison

| Template | Presentation Layer | Domain Layer | Data Layer | Use Case |
|----------|-------------------|--------------|------------|----------|

## Post-Generation Checklist

- [ ] Update `{name}_params.dart` with actual request parameters
- [ ] Update `{name}_model.dart` with actual response fields
- [ ] Add API endpoint to `ApiEndpoints` enum
- [ ] Update datasource implementation with correct endpoint
- [ ] Customize UI in `{name}_view.dart` (if using view templates)
- [ ] Add dependency injection for new classes
- [ ] Test the generated code

## Common Customizations

### 1. Request Parameters
```dart
// In {name}_params.dart
class ProfileParams {
  final String userId;
  final bool includeDetails;

  ProfileParams({
    required this.userId,
    this.includeDetails = false,
  });

  Map<String, dynamic> toJson() {
    return {
      'userId': userId,
      if (includeDetails) 'includeDetails': includeDetails,
    };
  }
}
```

### 2. Response Model
```dart
// In {name}_model.dart
class ProfileModel {
  final String id;
  final String name;
  final String email;

  ProfileModel({
    required this.id,
    required this.name,
    required this.email,
  });

  factory ProfileModel.fromJson(Map<String, dynamic> json) {
    return ProfileModel(
      id: json['id'],
      name: json['name'],
      email: json['email'],
    );
  }
}
```

### 3. API Endpoint
```dart
// In api_endpoints.dart
enum ApiEndpoints {
  // ... existing endpoints
  fetchProfile('user/profile'),
  updateProfile('user/profile/update');
  
  final String value;
  const ApiEndpoints(this.value);
}
```

### 4. Dependency Injection Example
```dart
// Register in your DI container
// Datasource
sl.registerLazySingleton<ProfileRemoteDatasource>(
  () => ProfileRemoteDatasourceImplementation(client: sl()),
);

// Repository
sl.registerLazySingleton<ProfileRepository>(
  () => ProfileRepositoryImplementation(remoteDatasource: sl()),
);

// Usecase
sl.registerLazySingleton(() => ProfileUsecase(sl()));

// Facade
sl.registerLazySingleton(() => ProfileUseCasesFacade(
  profileUsecase: sl(),
));

// BLoC
sl.registerFactory(() => ProfileBloc(usecases: sl()));
```

## Troubleshooting

### Issue: Import errors after generation
**Solution:** Run `dart pub get` or `flutter pub get`

### Issue: Template variables not replaced
**Solution:** Ensure you're using the correct Mason version and run `mason get`

### Issue: Files generated in wrong location
**Solution:** Check your brick paths in `mason.yaml`

### Issue: Compilation errors
**Solution:** 
1. Check all imports are correct
2. Verify your `ApiEndpoints` includes the new endpoint
3. Ensure DI is properly configured
4. Run `flutter clean` and rebuild

## Tips

- **Start with `_view` templates** for new features, they generate everything
- **Use `_integration` templates** when adding endpoints to existing features
- **Always customize** the generated models to match your API
- **Test incrementally** - datasource → repository → usecase → bloc
- **Use consistent naming** across module and feature names
